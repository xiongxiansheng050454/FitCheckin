# 有限训练周期

## 使用流程

在计划页的「周模板」中新建轻度模板，再复制并调整为中度模板。
进入「安排周期」，选择轻度并连续添加4周，再选择中度并添加4周。
保存后，周一至周日按所选模板执行；第5周自动切换到中度，8周结束后停止。
可以提前安排下一段周期，默认接在最后一个已排周期之后，也可另选本周或未来的起始周。
周期之间允许空档，日期不可重叠。每个周期1至52周，累计保存最多520周、100个周期。

## 可复用周期模板

计划页增加「周期模板」，支持新建、修改、复制、删除和安排。模板由有序周模板ID组成，可批量添加轻度4周、中度4周，支持逐周替换、排序和删除，保存后可一次续排整个8周。已有周期也可「存为周期模板」。

`cycleTemplate` 实体保存 `{id,name,weeks:[weeklyTemplateId]}`，每个模板1至52周。周期模板引用周模板的最新参数，安排时生成独立快照；之后修改或删除周期模板不会改变已排周期。被引用的周模板需先从周期模板移除才能删除；远端缺失的引用会明确标记并允许替换。启动/拉取新增 `cycleTemplatesSupported:true`，客户端按环境及账号缓存能力。复用现有两个集合、队列和版本冲突机制。

## 已排周期数据

`program:program` 是一个整体版本的日历安排，沿用应用/用户隔离、持久队列、事务去重和冲突处理。启用周期后，生效安排历史 `scheduleHistory` 也保存在此实体内，避免用户选取云端周期后本地历史仍按另一份周期判断。首次保存会继承旧个人设置中的安排历史。

```js
{
  id: 'program',
  from: '2026-10-05',
  scheduleHistory: [/* 生效日期与各周训练日位图 */],
  cycles: [{
    id: 'cycle-id', name: '8周渐进', startWeek: '2026-10-05',
    plans: [{id: 'snapshot-id', templateId: 'template-id', name: '轻度', days: [/* 7天 */]}],
    weeks: ['snapshot-id' /* 每周一个快照ID */]
  }]
}
```

一个周期内重复使用同一快照，避免为4个轻度周复制4份动作数据。
周模板修改或删除不影响已排周期。更换未来某周的模板时保存新快照。
单周覆盖增加 `cycleId` 和 `planId`，只应用于对应周期中的对应快照；更换模板后旧覆盖失效。
开始过的当天仍以日记录为准，过去的周安排不能修改或删除；已开始的周期不能移动起始日期。
仅未来周期可取消，已到期周期继续保留。到期不代表每次训练都完成，界面使用「已到期」。

首次安排新周期时，旧每周循环保留到 `from`。
本周开始的周期从创建当天生效，过去日期和历史连胜安排保持原样。
未来开始的周期从起始周一生效；到期后不会回退到旧循环。
提前安排更早的周期可以把尚在未来的 `from` 提前，但不能追溯过去。

`bootstrap`/`pull` 新增 `cyclesSupported:true`。客户端缓存此能力；后端未更新时，保存周期会提示刷新，避免发送旧后端不认识的实体。
不需要新增集合、索引、API Key或权限。现有两个管理员专用集合继续使用。

## 自动验证

`tests/cycles.test.js` 连接实际本地 store、云函数 handler、文档事务模型和原生页面 JS：

- 4+4周安排、周一切换、8周结束、跨年和闰日。
- 模板删除后快照仍可执行、周覆盖恢复、开始后的当日参数不变。
- 更换周模板后旧覆盖失效，独立设备读到一致安排。
- 旧循环到首个周期开始的兼容性，周期结束后不恢复循环。
- 休息日/周期空档不打断连胜，漏练有安排的日期会中断。
- 断网重启、跨北京时间午夜、丢失回执重试只写入一次。
- 两设备整体版本冲突、草稿版本检查、周期重叠拒绝、用户隔离。
- 客户端及服务器均阻止修改过去周、移动或删除已开始周期。
- 服务端拒绝缺少周模板、非法动作、未知字段、重叠日期、超长周期和删除整个日历。
- 原生周期编辑页面批量添加4+4周，并经实际本地 store/backend 保存。
